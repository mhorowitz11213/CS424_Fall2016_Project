INTERACTIVE HEADWAY IMBALANCE AND BUNCHING DIAGNOSTIC
Vega-Lite Visualization: Code Documentation and Implementation Process

============================================================
1. OVERVIEW AND PURPOSE
============================================================

This visualization is an interactive scatterplot designed to
examine CTA bus headway regularity using observed intervals
between consecutive buses.

It builds upon the static version of the Headway Imbalance
and Bunching Diagnostic by introducing several interactive
features.

The visualization compares two measurements:

1. Observation Previous:
   The number of minutes between the previous bus and the
   currently observed bus.

2. Actual Next:
   The number of minutes between the currently observed bus
   and the next bus.

The purpose is to identify differences between the spacing
before and after an observed bus.

These differences can reveal irregular service, bus bunching,
and unusually long gaps between buses.

The interactive visualization provides four main features:

1. Route filtering:
   Users can select an individual CTA route or display
   observations from all routes.

2. Direction filtering:
   Users can select a travel direction or display all
   directions.

3. Hover tooltips:
   Users can hover over individual points to inspect detailed
   information about the corresponding bus observation.

4. Zooming and panning:
   Users can zoom into particular regions of the scatterplot
   and move around the chart to examine observations more
   closely.

The visualization also includes a diagonal reference line
representing equal headways.

Points on the diagonal indicate that the previous and
following intervals are equal.

Points above or below the diagonal indicate differences
between the two intervals.

4. LAYERED VISUALIZATION STRUCTURE
============================================================

"layer": [
    {...},
    {...}
]

The layer property allows multiple visualization layers
to be combined into one chart.

The specification contains two primary layers.

Layer 1:
A diagonal reference line representing equal headways.

Layer 2:
The interactive scatterplot containing the actual bus
observations.

The layered structure allows both layers to share the
same coordinate system.

This makes it possible to compare observations directly
against the reference line.

The first layer provides a constant visual benchmark.

The second layer responds to user interactions.

7. SECOND LAYER: INTERACTIVE SCATTERPLOT
============================================================

The second layer contains the bus observations.

It also introduces an additional interactive parameter
for zooming and panning.

The data is represented using a values array containing
individual JSON objects.

Each object represents one bus observation.

The records contain the following fields:

"id"

This identifies an observation within the supplied data.

Some IDs are reused at different stops, so they should
not be interpreted as globally unique record identifiers.

"route"

This specifies the CTA bus route number.

Examples include routes 8, 20, 22, 36, 56, 66, 146,
147, and 157.

"stop"

This specifies the bus stop or intersection where the
observation was recorded.

Examples include:

- Halsted and Fulton
- Grand and Kingsbury
- Clark and Washington
- La Salle and Madison
- Lake and Halsted
- Sheridan and Granville
- Clark and Devon
- Michigan and Randolph
- Broadway and Wilson
- Foster and Marine Drive

"cta"

This contains the CTA stop identifier associated with
the observation.

It distinguishes stops that might otherwise have
similar or related names.

"direction"

This specifies the direction of travel.

N = Northbound
S = Southbound
E = Eastbound
W = Westbound

"previous"

This stores the number of minutes between the previous
bus and the currently observed bus.

It determines the horizontal position of the point.

"actualNext"

This stores the number of minutes between the currently
observed bus and the next bus.

It determines the vertical position of the point.

"comments"

This contains contextual information about the observation.

Examples include:

- Early or late arrivals.
- Buses arriving close together.
- Possible bunching.
- Long service gaps.
- Observations of relatively regular service.

These comments are displayed through the hover tooltip.

9. DATA TRANSFORMATIONS AND FILTERING
============================================================

"transform": [
    {...},
    {...},
    {...}
]

The transform property applies filtering operations
before the observations are displayed.

The specification contains three filters.

------------------------------------------------------------
9.1 INVALID OBSERVATION FILTER
------------------------------------------------------------

{
    "filter": "datum.previous != 999 &&
               datum.actualNext != 999"
}

This filter excludes observations containing the
sentinel value 999.

datum.previous != 999

This checks that the previous interval is not equal
to 999.

datum.actualNext != 999

This checks that the actual following interval is
not equal to 999.

The && operator means that both conditions must be true.

Therefore, an observation is displayed only when both
headway measurements are valid.

Zero-minute intervals are retained because zero can
represent a valid observed interval.

------------------------------------------------------------
9.2 ROUTE FILTER
------------------------------------------------------------

{
    "filter": "routeFilter === 'All' ||
               datum.route === routeFilter"
}

This transformation connects the route dropdown to
the observation dataset.

routeFilter === 'All'

This checks whether the user selected All routes.

If the condition is true, observations from every
route are retained.

datum.route === routeFilter

This checks whether the route associated with an
observation matches the selected dropdown value.

The || operator means OR.

Therefore, an observation is retained when either:

1. The user selected All routes.
2. The observation belongs to the selected route.

For example, selecting Route 8 displays only records
where datum.route is equal to "8".

The route filtering operation updates the scatterplot
when the dropdown selection changes.

------------------------------------------------------------
9.3 DIRECTION FILTER
------------------------------------------------------------

{
    "filter": "directionFilter === 'All' ||
               datum.direction === directionFilter"
}

This transformation connects the direction dropdown
to the observation dataset.

directionFilter === 'All'

This checks whether the user selected All directions.

If true, observations from all directions are retained.

datum.direction === directionFilter

This checks whether the observation's direction matches
the selected direction.

The || operator means OR.

An observation is therefore retained when either:

1. The user selected All directions.
2. The observation belongs to the selected direction.

For example, selecting North (N) displays only records
where datum.direction is equal to "N".

The route and direction filters are applied together.

For example, selecting Route 8 and North (N) displays
only northbound observations belonging to Route 8.

14. FILL ENCODING: DIRECTION DISTINCTION
============================================================

"fill": {
    "condition": {
        "test": "datum.direction === 'N' ||
                datum.direction === 'W'",
        "field": "route",
        "type": "nominal",
        "scale": {
            "domain": [...],
            "range": [...]
        }
    },
    "value": "white"
}

The fill encoding determines the interior color of
each scatterplot point.

It uses a conditional expression based on direction.

The purpose is to distinguish northbound and westbound
observations from southbound and eastbound observations.

"condition": {...}

This specifies that the fill should depend on a condition.

"test": "datum.direction === 'N' ||
        datum.direction === 'W'"

This checks whether the observation direction is
northbound or westbound.

The || operator means OR.

If the observation is northbound or westbound, the
condition evaluates to true.

"field": "route"

When the condition is true, the point interior is
assigned the color associated with its route.

"type": "nominal"

This specifies that the route is categorical data.

"scale": {
    "domain": [...],
    "range": [...]
}

This uses the route color scale to determine the
interior color.

" value": "white"

When the condition is false, the point interior
is set to white.

Therefore, the intended encoding is:

Northbound (N):
Filled circle using the route color.

Westbound (W):
Filled circle using the route color.

Southbound (S):
White interior with a colored outline.

Eastbound (E):
White interior with a colored outline.

The stroke encoding continues to provide the route
color for the circle outline.

This allows direction to be distinguished through
the fill while route identity is represented through
color.

17. INTERACTION DESIGN AND USER WORKFLOW
============================================================

The interactive visualization supports several
different ways of exploring the bus observations.

ROUTE EXPLORATION

The user begins with all routes displayed.

They can select a specific route using the Route dropdown.

The scatterplot updates to show only observations
belonging to that route.

This makes it easier to examine route-specific
headway patterns.

DIRECTION EXPLORATION

The user can select a particular direction.

The scatterplot then displays only observations
belonging to that direction.

This allows comparisons between northbound,
southbound, eastbound, and westbound service.

COMBINED FILTERING

The route and direction filters can be used together.

For example:

Route: 8
Direction: N

This combination displays only northbound observations
from Route 8.

Using both filters allows users to narrow the dataset
to a particular route-direction combination.

HOVER FOR DETAILS

The user can move the pointer over an individual point.

The tooltip displays:

- Observation ID
- Route
- Direction
- Stop
- CTA Stop ID
- Previous gap
- Actual next gap
- Comments

This interaction provides details without requiring
all the information to appear permanently on the chart.

ZOOM AND PAN

The user can interact with the coordinate scales.

Dragging allows the user to move around the chart.

Scrolling allows the user to zoom in or out.

This is useful when several observations overlap or
when users want to inspect a smaller region.

============================================================
18. HOW TO INTERPRET THE SCATTERPLOT
============================================================

Each point represents one bus observation.

The horizontal coordinate represents the interval
between the previous bus and the currently observed bus.

The vertical coordinate represents the interval
between the currently observed bus and the next bus.

The dashed diagonal represents equal intervals.

POINTS ON THE DIAGONAL

A point on the diagonal indicates that the previous
and following intervals are equal.

Example:

Previous = 10 minutes
Actual Next = 10 minutes

This indicates balanced spacing around the observed bus.

POINTS ABOVE THE DIAGONAL

A point above the diagonal indicates that the following
interval is longer than the previous interval.

Example:

Previous = 5 minutes
Actual Next = 15 minutes

The observed bus was followed by a longer gap than
the gap preceding it.

This can indicate a service gap following closely
spaced buses.

POINTS BELOW THE DIAGONAL

A point below the diagonal indicates that the following
interval is shorter than the previous interval.

Example:

Previous = 15 minutes
Actual Next = 5 minutes

The observed bus was followed by another bus relatively
quickly.

This can indicate a short following interval and may
be associated with bunching.

POINTS NEAR THE ORIGIN

Points near (0, 0) indicate short intervals both before
and after the observed bus.

These observations may indicate buses arriving
close together.

POINTS FAR FROM THE ORIGIN

Points farther from the origin indicate longer intervals.

For example, a point near (30, 30) indicates that
the observed bus had approximately thirty-minute
intervals on both sides.

============================================================
19. IMPLEMENTATION PROCESS
============================================================

The interactive visualization was implemented using
a layered Vega-Lite specification.

The implementation process can be summarized as follows.

STEP 1: ORGANIZE THE OBSERVATION DATA

Bus observations were represented as individual JSON
records.

Each record contains the route, stop, CTA identifier,
direction, previous headway, actual following headway,
and contextual comments.

This structure preserves individual observations
rather than aggregating them into route-level averages.

STEP 2: DEFINE THE INTERACTIVE PARAMETERS

Two dropdown parameters were created.

The routeFilter parameter allows users to select
a particular CTA route.

The directionFilter parameter allows users to select
a travel direction.

Both parameters default to All.

STEP 3: CREATE THE REFERENCE LINE

A separate dataset containing two points was created.

These points define a diagonal line from (0, 0) to
(60, 60).

The line provides a benchmark for comparing previous
and following headways.

STEP 4: CREATE THE SCATTERPLOT

The observation dataset was added as the second layer.

Each valid observation is represented by an individual
circular point.

The previous headway determines the horizontal position.

The actual following headway determines the vertical
position.

STEP 5: ADD ZOOMING AND PANNING

An interval selection parameter named zoomPan was added.

It is bound to the chart scales.

This allows users to interact with the coordinate system
and inspect smaller regions of the scatterplot.

STEP 6: IMPLEMENT DATA FILTERING

Three filter transformations were applied.

The first removes observations containing invalid
sentinel values.

The second filters observations based on the selected
route.

The third filters observations based on the selected
direction.

These transformations allow the scatterplot to update
dynamically in response to user selections.

STEP 7: APPLY ROUTE COLOR ENCODING

The stroke encoding assigns a consistent outline color
to each bus route.

The route color scale uses an explicit domain and range.

This makes route categories visually distinguishable.

STEP 8: APPLY DIRECTION FILL ENCODING

The fill encoding uses a conditional expression.

Northbound and westbound observations receive colored
interiors.

Southbound and eastbound observations receive white
interiors.

This provides an additional visual distinction between
travel directions.

STEP 9: IMPLEMENT HOVER TOOLTIPS

The tooltip encoding was added to the point marks.

It exposes additional observation information when
the user hovers over an individual point.

This follows the details-on-demand interaction principle.

STEP 10: APPLY FINAL STYLING

The final configuration defines the chart border,
axis fonts, legend fonts, and other visual properties.

These settings improve readability and maintain
a consistent visual appearance.

============================================================
20. DESIGN RATIONALE
============================================================

The scatterplot was selected because it allows two
quantitative measurements to be compared simultaneously.

The previous and following headways are displayed
on separate axes, making differences between the two
intervals visible.

The diagonal reference line provides an immediate
visual benchmark for identifying balanced headways.

The route dropdown allows users to isolate particular
routes without needing separate charts.

The direction dropdown supports comparisons between
different travel directions.

The two filters can also be combined, allowing users
to examine a specific route-direction combination.

The route color encoding makes it possible to identify
the route associated with each observation.

The filled and hollow circle encoding adds another
categorical distinction without requiring separate
visualizations.

The tooltip interaction provides additional information
without overcrowding the chart.

Finally, zooming and panning allow users to examine
dense regions and overlapping observations in greater
detail.

Together, these design decisions support a more flexible
exploration of bus headway imbalance and irregular
service patterns.

============================================================
21. TECHNICAL NOTES AND VALIDATION
============================================================

Several implementation details should be checked when
using this specification.

1. VEGA-LITE VERSION

The specification declares Vega-Lite version 6.

The JavaScript libraries used to render the visualization
must be compatible with Vega-Lite version 6.

If the surrounding HTML page loads Vega-Lite version 5,
the schema and runtime versions do not match.

The Vega, Vega-Lite, and Vega-Embed libraries should
be checked for compatibility.

2. ROUTE COLOR DOMAIN AND RANGE

The route color domain contains nine values:

8, 20, 22, 36, 56, 66, 146, 147, 157

However, the supplied range contains ten colors.

Only nine colors are required for the nine route
categories.

The extra color should be removed unless another
route category is intended.

The same correction should be applied to both the
stroke scale and the conditional fill scale.

3. DIRECTION ENCODING

The subtitle states:

Solid = N/W
Hollow = S/E

The fill condition implements this convention.

Northbound and westbound observations receive their
route-associated fill color.

Southbound and eastbound observations receive white.

The stroke encoding continues to provide colored
outlines for all observations.

4. FILTERING BEHAVIOR

The route and direction filters are applied after
the invalid observation filter.

This means that observations containing 999 in either
headway field are excluded regardless of the selected
route or direction.

5. ZERO-MINUTE INTERVALS

Zero-minute intervals are retained.

They can represent buses arriving within the same
recorded minute.

The filter excludes 999, not zero.

6. AXIS DOMAINS

Both axes use a fixed domain from zero to sixty minutes.

This ensures that the diagonal line represents equality.

However, observations greater than sixty minutes would
fall outside the displayed range.

7. ZOOM AND PAN

The zoomPan parameter uses an interval selection
bound to scales.

It enables interaction with the scatterplot's
coordinate system.

The reference line is in a separate layer, so its
behavior should be checked when users zoom or pan.

8. TOOLTIP DATA

The tooltip references fields that are present in
the observation records.

These include:

id
route
direction
stop
cta
previous
actualNext
comments

The tooltip therefore provides both numerical and
contextual information about each observation.

9. DATA IDENTIFIERS

The id field is reused across different stops.

It identifies observations within their respective
sequences but is not a globally unique identifier.

The route, stop, and CTA fields provide additional
context for distinguishing observations.

10. JSON VALIDITY

The specification must remain valid JSON.

Comments such as // explanation cannot be inserted
directly into the JSON file.

Documentation should be stored separately from the
visualization specification.

============================================================
22. COMPARISON WITH THE STATIC VISUALIZATION
============================================================

The interactive visualization builds upon the static
Headway Imbalance and Bunching Diagnostic.

Both versions share the same fundamental analytical
structure.

They use:

- The same previous and actual following headway
  measurements.
- A scatterplot representation.
- A diagonal equality reference line.
- Quantitative axes with matching domains.
- Route-associated colors.
- Filled and hollow circle distinctions.

However, the interactive version introduces additional
functionality.

STATIC VERSION

The static version presents all observations at once.

It provides a fixed view of the data.

Users can inspect the overall distribution of points,
but they cannot dynamically isolate a route or direction
through the visualization itself.

INTERACTIVE VERSION

The interactive version adds:

- Route dropdown filtering.
- Direction dropdown filtering.
- Combined filtering.
- Hover-based details-on-demand.
- Zooming.
- Panning.

These features allow users to investigate particular
subsets of the data and inspect individual observations.

The interactive version therefore supports a more
exploratory analytical workflow.

============================================================
23. CONCLUSION
============================================================

The interactive Headway Imbalance and Bunching Diagnostic
provides a scatterplot-based approach for examining
CTA bus headway regularity.

It compares the interval preceding an observed bus
with the actual interval following that bus.

The diagonal reference line represents equal headways,
while deviations from the line reveal differences
between consecutive intervals.

The route dropdown and direction dropdown allow users
to filter observations dynamically.

The route color encoding and direction-based fill
encoding provide categorical distinctions.

The hover tooltip exposes additional information about
individual observations, including stop identifiers,
headway measurements, and contextual comments.

The zooming and panning interaction allows users to
inspect smaller regions of the scatterplot.

Together, these features provide an interactive
environment for exploring potential bus bunching,
short following intervals, long service gaps, and
relatively balanced service patterns.

The layered Vega-Lite implementation combines
interactive parameters, data transformations,
quantitative encodings, categorical scales, tooltips,
and chart styling into one visualization.
